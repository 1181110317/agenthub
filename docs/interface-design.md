# Interface design

Agent management is the visual reference for every built-in workspace. `public/design-system.css` is loaded after page styles and defines the shared type scale, controls, surfaces and states. Page styles retain their layout and responsive behavior.

| Component | Shared scale |
| --- | --- |
| Page title | 24px / 32px; 22px on narrow screens |
| Dialog title | 18px / 26px; 16px on narrow screens |
| Section heading | 14px / 22px |
| Interface text and form fields | 13px / 20px |
| Compact actions and navigation | 12px / 20px |
| Supporting text | 11px / 19px |
| Standard control | 36px tall, 8px corners |
| Compact action | 30px tall, 8px corners |
| Icon-only compact action | 30px square |
| Card / application shell | 10px / 14px corners |

Use existing theme variables for all colors. User-selected application, conversation and code fonts remain available. Coding surfaces retain the code font; Markdown and equations retain their document hierarchy.

The login form retains 16px mobile inputs to avoid browser focus zoom. Its desktop fields use the regular 13px interface scale. Native file-picker buttons use the same control shape as other forms.

Use `AgentHubIcons.svg(name)` for application controls and `AgentHubIcons.agent(id)` for Agent marks. The latter emits a safe, known `data-agent-icon` value for shared colors across the catalog, sidebar, session tabs and message headers. Button state changes should update the SVG and accessible label together.

Application controls use a 24px drawing grid, 1.75px rounded strokes and fixed 16–18px display sizes. Keep settings on a gear, runtime configuration on sliders, models on a cube, and the workbench on a four-tile mark so distinct destinations stay recognizable. Appearance uses a balanced half-light disc and the label “外观” on desktop; narrow layouts keep its 36px target and accessible name. Theme selection uses the same SVG check in Appearance and Settings, positioned over the preview without covering its caption.

Agent marks use selected, locally bundled [Lobe Icons](https://github.com/lobehub/lobe-icons) SVGs: OpenAI for Codex, Z.ai for ZCode, and the corresponding Claude, Gemini, DeepSeek, OpenCode, WorkBuddy and Cursor marks. Built-in execution and ordinary chat use a generic conversation mark. Keep native brand silhouettes intact, without decorative avatar tiles. Claude and DeepSeek retain their brand colors, ZCode uses the theme accent, and Gemini/WorkBuddy use the upstream multicolor SVGs. OpenAI/Codex and other monochrome brands follow the theme foreground; do not add a green tint to Codex. Session-list and tab glyphs are 14px, message-header glyphs 18px and catalog glyphs 22px. Uploaded images retain their own colors. The website uses a link mark; the favicon and initial HTML fallback match it. Use `capabilities` for the capability center and reserve `book` for skill documents.

`public/agent-identity.js` manages appearance overrides under `ah.identity.v1` in browser local storage. Users can change an Agent's default icon from its detail avatar, override one session from its More menu, and upload a workspace Logo from Appearance. The precedence is session override, Agent override, native brand. Clearing a session override follows the current Agent default. Existing DOM marks update in place, and same-origin browser tabs synchronize using the storage event. These are browser appearance preferences and are not synchronized through the backend or included in server backups.

PNG, JPG, WebP and standalone SVG uploads are limited to 2 MB, contained within a 128px square without distorting their aspect ratio, then saved as PNG. SVGs containing scripts, event handlers, foreign objects or external resources are rejected. Individual images, preference count and total stored size are bounded. Failed decoding or storage writes preserve the previous preference. The selected brand bundle is about 8.4 KB and adds no framework, CDN dependency, polling or animation.

Use `.fld` for fields, `.dialog-actions` for page-level actions, `.feature-panel` for tool sections, and `.feature-toolbar` for filters. A `.fld` directly inside a form grid has no outer margin: the grid owns its spacing. Keep custom native selects hidden and use the existing accessible select-button adapter.

Compact actions, including file-upload labels, use inline flex with centered icons and a 6px gap. Direct SVGs and enhanced `.ui-icon-slot` wrappers share a fixed 16px size in regular and compact buttons; icons must not shrink or depend on the text baseline. The low-specificity alignment defaults allow components to retain intentional grid or vertical layouts. Direct `.dialog-actions` buttons and upload labels use the same 36px control height and 13px text, while compact toolbar actions retain their 30px scale. Keep file inputs and legacy glyph spans hidden so they do not take up a flex slot.

Check the page frame, scrolling content, long labels, empty/error states, keyboard focus and read-only behavior. Verify compact and regular controls separately. Responsive acceptance uses the actual browser UI through CUA; screenshots and computed control measurements are evidence, while syntax and CSS structure checks provide supporting coverage.

Styling changes require a page reload. Backend activation is tracked separately when a previous feature introduces new API routes.

## Project and session navigation

The project name's first character and the Agent mark in its session rows share the same horizontal start. Unread dots, multi-select checkboxes and running indicators occupy the gutter; they must not push the Agent mark sideways. Pins stay inside their computer and project group. A collapsed group keeps pinned sessions and the active session reachable without rendering every preceding row.

The session title ellipsis, sidebar row ellipsis and row context menu use the same command list. Keep the title button's width within its flex allocation so its hitbox cannot cover adjacent controls. The menu fits the viewport, scrolls vertically when necessary, supports keyboard navigation and distinguishes disabled and destructive commands. Archived sessions remain available through the archive entry.

Workbench rows show the Agent mark, session title, target and state together. Desktop actions share the row; narrow layouts wrap them. Skill and MCP pages use explicit Agent and computer selectors, source labels and target-specific errors. A failed remote request must not substitute local content.

## Content and disclosures

Markdown block containers use normal whitespace; code and thinking retain their own preformatted rules. Paragraph spacing comes from margins rather than inherited literal newlines. Empty panels use a compact illustration or icon, a useful explanation and an available next action.

File changes, file references and reply image attachments share a thin themed border, a compact tinted heading with an icon and count, consistent actions and a 16px gap between sections. Keep the reply text outside these sections. File references show a file mark, filename, muted directory and the existing preview action. Show four references initially and reveal the remainder with one small action. Truncate long names and put the directory below the filename. Markdown delimiters cannot join adjacent references into a fake extra path.

Reply image attachments use the same heading and muted count, followed by three thumbnails. One compact action reveals the remaining images and preserves that choice during attachment updates. Use a three-column thumbnail grid on narrow screens. Count safe, unique URLs, keep lazy loading and the existing zoom viewer, and preserve aspect ratios. Images belonging to a tool keep their existing behavior.

Each reply has one lightweight process disclosure containing its intermediate explanations, tools, thinking and diagnostics in chronological order. Follow the compact conversation style observed in Codex and DeepSeek Harness: the outer control is a plain status row with a fine bottom separator, nearby counts and a small chevron. Show the actual running, completed, stopped or ended state; do not label stopped or failed history as successfully completed. Keep the accessible process label, visible keyboard focus and all original counts. The process starts open while running, then closes as a whole at completion. Completed history starts closed, and the final answer remains directly visible outside it. Keep actionable errors and question receipts visible. Closed long tool and thinking bodies render on demand.

Inside that process, display explanations in the same font, color and paragraph rules as ordinary replies. Consecutive tool runs use unboxed, content-sized summary rows with a standard small icon, an action caption such as reading files or running commands, a count with its unit, a nearby chevron, reliable line totals and active or failed states. Keep the original category counts in the tooltip and expanded breakdown. Do not repeat a separate thought count beside every tool caption. Group headings have no filled surface or outer frame, and the whole process has no decorative indentation or vertical rail. Only concrete tool details are inset below their summary. Preserve chronological order, reliable statistics, independent command disclosures, lazy rendering, user expansion choices while streaming and whole-turn closure at completion. Narrow columns wrap metadata without horizontal overflow.

A detached background reply still owns its process through its timeline. Do not create another process merely because it is disconnected from the document. Keep lazy-body renderers owned by live replies when replacing a history view. Upward wheel, touch and keyboard input pauses output following immediately, including within 400px of the bottom; new output and questions must respect that intent. Explicitly returning to the bottom resumes following, and background replies cannot scroll the current chat. Streaming and settled Markdown share normal whitespace, type and paragraph rules, while code and thoughts retain preformatted content.

Place the durable queue above the project/context row and keep its width aligned with the composer. Use a light themed surface, compact edit/remove actions and a More menu for priority, immediate delivery and ordering. Editing withdraws the item through the revision-checked queue API before restoring its text and attachments to the main composer and session draft. Preserve an existing draft and protect navigation races; failed withdrawal cannot discard a queued item.

Show tool-recorded file changes directly after the answer. Keep the workspace before/after snapshot in a separate, initially closed file list of the same width; show filenames, muted parent paths, operation labels and line totals rather than a nested folder tree. Disclose that concurrent tasks can contribute to workspace changes. Short replies can show an explicitly approximate whole-turn token rate; missing timing or reliable token counts must remain unknown. The common image viewer supports pointer-centered wheel zoom, panning, double-click reset and keyboard zoom without changing safe URL handling.

Do not render empty or invisible thinking records. Merge only adjacent thoughts with compatible known message, request and item boundaries, retaining paragraph breaks and the original stored records. Tools, narrative, errors and the final answer separate thought groups. Count displayed thought groups in the process summary; a merged row may show its original segment count. Delta-only thinking settles at the next content boundary and on completion. A distinct next thought must not overwrite an unfinished thought as if it were a cumulative snapshot. Native Codex messages still complete at their own item boundary without repeating turn snapshots.

Tool summaries use a stable 16px icon slot, a 32px row and one independent 12px chevron. Keep the tool mark visible on hover; command summaries use “运行命令”. The process and read-output wrappers have no height cap or scrolling of their own. Long read results have one code scroll area with line numbers and syntax highlighting; “展开全文” removes that height cap so the conversation owns vertical scrolling. The nested `pre` must not introduce another scrollbar. Command inputs/outputs share one bounded scroll area rather than separately scrolling each nested section. Expanded thinking follows the conversation scroll. Use small themed code surfaces without a surrounding timeline rail or sweep animation.

File-edit and write step headers also show line counts. Reuse the bounded file-operation calculation and cache results by unchanged tool objects. Successful, completed known changes contribute to the compact group's totals; failed and pending operations do not. Pending counts carry a short “待完成” note. A write without its prior snapshot shows its written length, and incomplete or replace-all fragments remain explicitly partial. Associate returned snapshots only through matching content or an unambiguous path; never borrow another same-path operation's counts. Both early and late snapshot events can update the current step without replacing its disclosure.

Running replies show a short activity label for thinking, tools, replies, pending user input or saving. After 30 seconds without a content event, show the actual silent duration; this is a status hint and does not stop the Agent. Derive it from the existing elapsed timer and skip drawing hidden or disconnected replies. Clear the running label at completion. A successful Claude-compatible `result` may carry the only final answer: display and persist that text before completion, without duplicating a complete answer already received. A distinct final answer after tools cannot overwrite earlier streamed commentary.

`public/conversation.css` owns the shared appearance of conversation approvals, questions, plans, the single process disclosure and reply attachments. These belong to the reply column and share its width and left edge. Approvals, questions, step checklists and the process retain their unboxed conversation layout. A Markdown plan document retains its original compact title row. Clicking it opens the full body in the existing right-side workspace as a virtual document tab. Reuse tabs for the same source and body, preserve existing file tabs and dirty buffers, hide filesystem-only actions for virtual plans, and retain save/implementation/download and read-only behavior. Escape closes the reader and returns focus to the connected title row. Keep checklist progress and all attachment/tool-summary styles at the user-selected rollback baseline; do not restyle them as part of the sidebar change. A missing file-diff snapshot is a muted information row with an optional reason, not another primary content heading. Attachment sections retain the light boundaries described above. Body text inherits the conversation font, size and line height, including the selected density and narrow-screen scale. Secondary labels and actions may use a smaller scale. The regular 13px interface scale still applies to management pages. Other workspace styles must not duplicate these component rules.

Approvals ask a short, natural question, followed by the requested path or command and horizontal actions that wrap on narrow screens. Keep the command or path in a small code surface, without enclosing the whole request in a card. Preserve the native distinction between allowing once, changing the session permission mode, remembering the project and denying. Retain the original tool title in the receipt. After a response, replace the form with one closed, muted receipt row; failure restores the available actions. Read-only views cannot submit approvals.

Group completed tool approvals and automatic project grants into one closed “权限记录” entry per reply. Its count distinguishes manual confirmations from automatic grants; expand it to see per-tool automatic counts and individual manual receipts. Persist the compact audit separately from tool blocks so completion, reopening and refreshing preserve it. Keep up to 200 manual details with the full cumulative count and disclose any omitted older detail. The audit records existing decisions and never grants a permission itself. Pending approvals and unrelated errors remain directly visible.

Questions use the same text hierarchy as replies. Show the current question's category once, followed by its question and a radio or checkbox text list. Options have a light background only when hovered or selected, without permanent boxes. Show one question at a time, retain answers when moving back, and submit the complete set once. Empty free answers stay disabled until text or an attachment is available. Bound the interaction by the actual message viewport: scroll the current question while keeping its heading and footer visible. Decide whether to follow new questions before inserting them, so the extra height cannot strand the actions below the viewport. A successful response becomes one closed, unboxed summary row with an optional answer record. Persist only the actual questions, answers and attachment names; option lists and local upload paths do not belong in that record.

Plans use an ordinary checklist with a compact heading and completed/total count. Completed steps use a fine check; the current step uses a small mark and text emphasis. Keep the accessible progressbar semantics without displaying a large progress track. Only native plan events change a step's status; tool names and the end of a turn cannot imply completion. Idle history shows the last reported progress. Continue the latest unfinished checklist across turns without resurrecting a checklist superseded by a completed plan. A Markdown proposal is labeled as a document and does not receive invented execution progress. Unfinished plans start open; live updates preserve the user's disclosure choice. Keep save/implementation and Markdown download actions together below the content. A compact, unboxed current-step entry above the composer opens the checklist; hide this duplicate entry once the plan is complete, while retaining the message history.

Plan editing and preview share one document surface with a persistent action footer and visible save state. Creating an implementation session inherits the source Agent, target, project and model configuration and the selected permission mode, then opens a draft for the user to send.

File changes use compact rows inside the shared attachment section, with an 18px file mark, filename, operation, line counts and preview/diff/undo actions. Keep the compact heading and fine row separators; narrow screens put actions below the filename. Counts describe tool operations, not Git's final net difference. Count complete unified hunks or compare known text fragments with bounded work; show partial or unavailable results explicitly. A write without an old snapshot reports its output length instead of claiming that every line was newly added. Cache statistics for unchanged operation objects and avoid an unbounded diff on the UI thread.

Conversation login notices follow the same unboxed text hierarchy, scoped to `#messages`. Keep the separate application login form's existing layout. Interactive text and disclosures retain a visible keyboard focus indicator.

Execution records use compact status and operation rows integrated into the reply column. The outer status, prose and operation rows share that column; only concrete tool bodies use a small inset. The outer status, elapsed time and counts use the reply's body size, including density preferences and narrow screens. Show whole-turn elapsed time beside the status, update it through the existing live timer, and retain the recorded duration in history; omit unknown durations. Avoid nested card surfaces, large icon tiles and strong bold process headings. File attachments and actionable approval forms retain their separate existing styles.

Tool filenames are underlined links to the existing file sidebar, including read, write, edit, native multi-file changes, explicit patch paths, image reads and directory listings. Clicking a file link must not toggle its tool disclosure. Keep concrete command disclosures and their lazy output unchanged. The shared Markdown renderer also recognizes inline-code paths, explicit local file links, line suffixes, directories, ordinary prose paths and local server addresses without a scheme. Fenced code stays literal, existing links cannot gain nested links, and unsafe URL schemes remain inactive. File and directory reads retain the current session target and the existing API access checks; missing files show an error rather than stale contents.

Session statistics show accumulated turn elapsed time, request output throughput and average first-token wait. Turn time includes tools, waiting and any gaps while the turn remains open; it is not continuous model work. Request throughput divides paired output tokens by paired request time, including the request's own waiting while excluding time between requests. Deduplicate request IDs and label measured coverage. Find the longest request gap inside each recorded turn without counting idle time between turns or inventing gaps between overlapping requests. Do not display the legacy streaming rate: old records do not distinguish tool/reasoning output. Average first-token wait divides the sum of recorded first-token timings by its own sample count, with coverage shown separately from request throughput; missing samples are unknown, not zero. It follows each Agent's recorded timing origin rather than promising total wait from clicking Send. Global statistics show the same latency metric once. A disclosure provides the actual numerators, denominators and wall-clock turn rate. Reply footers use whole-turn output and elapsed time with an approximate label, never legacy streaming timing. These views use existing ledger data and add no polling.

## Composer configuration and file layouts

Composer configuration uses 34px fields with a 12px / 20px label/value scale, fixed 15px icons and centered chevrons. Permission, provider and reasoning use the same control shape. Reasoning is managed through its menu; there is no duplicate deep-thinking switch. Keep permission descriptions in the menu and preserve each Agent's existing permission semantics. Narrow screens put permission and reasoning in two columns and give the provider its own full-width row; long provider names truncate inside their field and remain available in the tooltip. Image and voice actions use compact SVG-and-label buttons on desktop, and icon-only buttons on narrow screens. Recording state updates its accessible pressed state.

Header actions use a consistent 32px height, 12px labels and 16px icons. The project, target, context and usage row above the input uses 30px controls and 12px labels. Keep today's usage and session usage on the same baseline as the other header actions, without an extra large background tile.

The file panel offers two layouts under **工作区 / 标签**. Workspace layout keeps the explorer beside the open documents; tab layout gives the directory its own tab. The layout choice and explorer width are browser preferences (`ah.reviewLayout`, `ah.reviewExplorerWidth`). Opening a closed file panel always starts docked beside the conversation, including browsers with the old `ah.reviewFilesWide` preference. Maximizing is explicit and lasts until the panel closes; selecting another document keeps the current size.

The document container stays mounted when changing layout or closing an unrelated tab. Preserve editor text, cursor and undo history. Closing a dirty document must retain the existing confirmation. Closing the panel retains its project buffers, and reopening returns to the previous document. Selecting a file reveals its parent directories once; refreshing must respect folders the user subsequently collapses.

The explorer owns its target, compact action row, search field, scrolling tree and status footer. The whole file panel owns one fixed 40px tab strip directly below its 48px heading, above both the layout toolbar and explorer/document split. Plan, blank, preview, edit and diff tabs share that strip; changing mode or showing the directory cannot move it. Overflow scrolls horizontally without changing its height, and selecting a tab reveals it. The document owns metadata/actions and content scrolling. Explorer width is bounded to 180–420px while preserving document space. At panel widths of 640px or less, the tree becomes a dismissible overlay; choosing a file returns to content, and the covered document is inert. The tab strip stays outside that covered region. File tabs and tree rows support keyboard navigation.

Files/plans and the task browser share the right side and are mutually exclusive, including when files are maximized. Opening either closes the other view before showing its own. Hiding the browser releases its human-control lease and polling, while its task page continues running under the existing browser lifecycle. Retain its address, pending text, element-picking option and width in a bounded, per-session memory cache; never cache control tokens or frames there. Restore file tabs and unsaved editor buffers by project without letting a cached document cover an open browser. Apply the cached active tab metadata before any tab persistence, so a hidden panel's empty mode/path cannot overwrite the saved editor. The Files action from a plan opens the directory using a blank file tab while retaining the plan tab. These switches preserve buffers within the current page; they do not promise draft recovery after a reload.

Text editors show a fixed horizontal number gutter, a current-line mark, total line count and cursor line/column. Blank and trailing lines count as document lines. Number rows are limited to the visible viewport; vertical scrolling keeps their baseline aligned with the text, while horizontal scrolling leaves the gutter fixed. Re-index lines on content changes and use binary search for cursor moves. Disconnect the editor's size observer and clear pending rendering timers when its view is replaced or closed.

All file calls retain the current session and target. Remote menus expose the remote project terminal instead of local OS application actions. Read-only views expose browsing and previews. Connection failures show their target and a retry action without displaying local files. Directory reads are lazy and do not introduce polling; a loaded empty directory is cached. Menus and confirmations must remain above a maximized file panel.

The file toolbar includes a project terminal toggle. Maximizing files moves the existing terminal node below the explorer/document area; restoring files returns the same node to the content wrapper. Preserve the PTY, input, tabs and scrollback through either move, and avoid reserving a second terminal gap in the conversation while files are maximized. The toggle follows the current session directory and target and is disabled in read-only views.
